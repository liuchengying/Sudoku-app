# 单机数独功能完善与验收记录

> 本文保留四轮计划首版完成时的范围与验证结果。此后已将三个题组升级为无限闯关，最新关卡规则与验收见 [无限闯关记录](INFINITE_CAMPAIGN.md)。

实施日期：2026-09-30。依据修改前评估的四轮计划，完成可靠性、题目体系、教学交互、长期目标与高级工具的第一版实现。变体规则仍作为独立扩展。

## 当前可玩范围

| 模式 | 题目与计分 | 入口 |
| --- | --- | --- |
| 固定关卡 | 大师、王者、宗师各 25 关，共 75 关；首次完成分别获得 2000、4000、10000 分 | 首页“固定关卡” |
| 无限练习 | 离线生成唯一解题目，入门、基础、进阶、专家四档；局数不限，不增加关卡积分 | 首页“无限练习” |
| 每日挑战 | 本地日期与生成版本决定题目；支持补玩、重玩、日历、当前/最长连续完成天数 | 首页“每日挑战” |
| 自定义题目 | 输入 81 个数字，空格用 0 或 .；验证行列宫、可解性和唯一解 | 首页“导入题目” |

所有模式复用存档、计时、撤销重做、候选、解法、奖牌和历史。生成局存档包含完整题目元数据，恢复、重开和结算不再依赖固定题库 ID。每个模式完成后均记录历史与完成局统计；每日天数按日期去重。

“无限”表示没有预设关数上限，采用种子生成与等价变换继续出题，并非数学意义上无限且永不重复；最近 100 道已取用题目会过滤重复。

## 第一轮：可靠性与基础体验

- 默认测试命令改用独立 Vitest 配置，避免加载 uni-app 的构建流程。显式声明 Vue 测试插件依赖，并使用与 Vue 对应的 SFC 编译器。
- 模板导航改由脚本函数处理，修复类型检查错误；开关事件兼容 uni 的事件类型。
- 提示内部判断独立于错误标红开关；遇到错误填写先引导修正，填入提示时再次核对答案。
- 数字键按真实正确填写判断完成，避免关闭即时错误后错误禁用。关闭即时检查时隐藏即时错误数量和正确剩余数量，错误仍计入最终成绩。
- 进度、历史、累计统计、每日记录和结算标识合为一次持久化提交。提交成功后才把游戏置为完成；失败可以重试，相同游戏不重复计分或新增记录。
- 自动存档失败显示提示。结算失败区分“棋盘已存档”和“当前页面仅保留内存”，冷启动恢复完整棋盘后仍有重试结算入口。
- 存储增加结构、棋盘、操作索引、快照和设置值检查，损坏数据不直接进入 Store。重置进度写入废弃游戏标识，避免清理失败时恢复旧局。
- 截断长 Timeline 时保存新的回放起点；没有 Timeline 的历史仅显示最终棋盘，不提供虚假的滑块步骤。
- 累计完成局数、时长、错误、提示、奖牌与分模式/分难度计数独立保存，不因历史裁切或删除而减少。历史序号独立递增。
- 奖牌序号改为响应式计算，历史卡片每次加载 20 条。
- 首页网格随内容排布，小屏改为 4 列；游戏页允许滚动，棋盘根据可用高度限制尺寸。数字键采用单键盘，主数字键与主要工具触摸区至少 48 CSS px；CSS px 不等同于真机 dp 的测量。

## 第二轮：题目体系与长期可玩性

固定题组名称、ID、题目顺序、答案和积分规则保持兼容，仅重新计算评分、技巧与实际难度标签。

| 实际分级 | 判定依据 | 原 75 关数量 |
| --- | --- | --- |
| 入门 | 只需要唯一候选 | 9 |
| 基础 | 唯一候选、隐藏唯一 | 41 |
| 进阶 | 当前求解路径需要区块排除、数组、X-Wing 等消除技巧 | 7 |
| 专家 | 当前逻辑引擎无法完整求解 | 18 |

该分级基于当前引擎的求解路径，“专家”表示超出已实现技巧的完整求解能力，不能据此断言题目必须回溯或在人类解题中一定更难。

生成流程先尝试新的唯一解挖洞题，再按实际技巧分级筛选。最多 24 次新题尝试、1500ms 的阶段预算；之后最多 200 次题库等价变换，逐次重新评级。无法满足指定难度时显示失败并允许重试，不把其他难度冒充为所选难度。

修复不对称挖洞只遍历半个棋盘的问题。生成间隙主动让出执行，页面提供取消，离开页面后不会用迟到的生成结果替换当前游戏。近期题目过滤与每档下一题缓存保存在本机；缓存失败不影响游戏业务存档。

运行期、固定题库校准和命令行生成统一使用 `src/core/sudoku/`。`npm run puzzle:generate` 默认产物为 `docs/generated/puzzles.json`，不会直接覆盖生产题库。

## 第三轮：教学与操作效率

- 解法按“观察位置 → 分步推导/候选消除 → 答案 → 填入”逐步展开，默认不显示答案。逻辑引擎保留真实的前置消除步骤，棋盘标出提示目标与消除格。
- 查看有效解法计入提示；同一待处理提示重复打开不重复计数。更换棋盘状态后再请求提示视为新提示。
- 教程增加入门实局练习入口；首次进入游戏提供规则、选格、填数、草稿和解法引导。
- 提供先选格与先选数字两种输入方式；数字优先支持连续点格，重复点同一数字可解除锁定。
- 更多菜单增加手动检查、保存/恢复书签；恢复书签属于可撤销操作，计时、错误、提示次数保留。
- 深色主题覆盖所有页面与底部弹层，并同步原生导航文字颜色；大字通过字号变量生效，限制字体在矮屏中过度放大。
- 相同候选高亮，错误增加文字标记；棋盘格和数字键提供行列、数值、候选和状态的读屏描述。
- 关闭“更多”恢复打开前的运行状态；原本暂停的游戏保持暂停。暂停时工具与数字键禁用。

## 第四轮：长期目标与高级工具

- 每日挑战采用本地日期与 `GENERATOR_VERSION = 1` 固定种子，当前生成算法版本内同一天题目一致；保留完整存档后不会因日期变化而换题。
- 日历支持历史日期补玩、完成标记与连续完成统计，月边界和闰日按本地日历处理。
- 本地成就包含初次完成、首枚金牌、完成 100 局、固定关卡全通与完成 7 天每日挑战；成就从累计结果派生，不依赖仍保留的历史列表。
- 每局一个棋盘书签；题目导入支持换行、空白、逗号和点号。当前为文字导入，不含图片识别。

## 验收记录与边界

`npm run check` 串行执行类型检查、Vitest、生产题库/评分校验和 UI 源码编译。现有 10 条 Core 用例与新增 38 条业务/组件/生成用例共 48 条通过；75 道生产题的唯一解与元数据校验通过；22 个 Vue SFC、11 个页面路由校验通过。

测试使用真实 Core、Pinia Store、Repository 和 Vue 内存渲染器，模拟 uni 本地存储与平台接口。覆盖存储失败、冷启动、重复结算、长局回放、历史迁移和裁切、提示纠错、书签、菜单暂停、不同种子的四档生成、缓存/取消、每日去重/连续天数和导入校验。结果见 `docs/validation/results/latest-tests.json`。

命令行出题入口使用每题组 1 道题的脚本样本验证，产物为 `docs/generated/pipeline-smoke.json`，并核对唯一解、答案、评分和技巧。

本次没有启动工程、操作浏览器或真机、执行 Git 操作。SFC 内存编译和组件事件测试不能替代 uni-app 原生/H5 构建、实际屏幕布局、触摸、系统字体、音效与震动验收，这些仍待相应环境验证。

升级首次从原有有效进度和现存历史初始化累计值。此前已被旧版本裁掉的历史没有足够数据恢复，不会凭空补算。新累计值包含完成局，不包含放弃或尚未完成的游戏时长与操作次数。历史保留最多 1000 条，详细回放最多 50 条，并按约 150 万 JSON 字符的预算优先归档较早回放；单局超大数据或设备存储不足仍由保存失败提示处理。

首次引导和实局入口已具备，逐技巧定制的交互教学关、更多高级逻辑技巧、变体数独和图片导入仍可作为后续独立需求。
