# 首批折叠屏适配与游戏交互优化

实施日期：2026-10-10。用户授权：“好的，开始执行吧”。本轮执行已评估的首批范围，重点兼顾主流内外屏、左右大折叠、上下小折叠和阔折叠。

## 已实施的行为

- **动态窗口与安全区：**共享响应式窗口宽高，尺寸事件以新窗口大小为准；返回前台补读，读取失败回退系统信息，尺寸异常保留上一次有效值。全局监听由消费者共享，最后一个消费者释放时解绑；缺少配套 API 时使用页面 resize。Android 方向配置支持四个方向。
- **游戏布局：**实际可用宽度至少 640px、去除上下安全区后高度至少 320px 时，棋盘与工具/数字键并排；其他窗口单列。棋盘保持完整正方形，宽度同时考虑所在区域和可用高度；短窗口保留约 306px 的可读尺寸（仍受实际宽度限制），通过页面纵向滚动访问操作，不强制把整局塞进屏幕。数字和候选字号依据实际棋盘调整。这里的 px 指应用可用窗口，不是设备物理像素或原生 dp。
- **公共页面：**12 个页面绑定响应式安全区变量，标题栏动态顶边；阅读内容宽度上限 760px，首页与历史可利用更宽空间，历史/首页部分卡片和统计在宽窗口分栏。rpx 字号有上下限；棋盘线宽和候选内边距使用稳定尺寸。引导保留滚动正文、固定按钮区；弹层按窗口高度分配可滚动内容，宽窗口使用有宽度限制的居中面板。
- **当前局连续性：**尺寸变化只影响布局数据，未调用开始、暂停、恢复或结算动作；原存档与游戏 ID 继续复用。原有前后台暂停偏好保持，页面隐藏时保存并清理显示计时器，重新显示时只创建一份计时器。真机发生原生重建的效果尚未验收。
- **暂停与继续：**检查、保存/恢复书签、全盘候选可以通过明确的菜单动作在暂停中执行；完成/取消后回到原运行状态，原来暂停的局保持暂停。恢复/重开确认期间不计时；隐藏/卸载后的迟到确认不能恢复或修改旧局。首页、选择页和每日的继续入口一致，导航失败暂停并提示重试。
- **每日挑战：**默认今日选择跨日/月时更新选择与日历；明确选择历史日期后保留补玩，增加回到今天；“继续这一天/开始今日挑战/开始补玩/再玩这一天”与实际动作对应。
- **解法：**打开说明不计算、不改变选中格，也不展示提示目标；点击“查看下一步推导”后请求并计入有效提示。说明明确是全盘下一步，并提前告知奖牌影响。棋盘未改变时同一步重复查看不重复计数，`lastHintKey` 随当前局保存；旧存档仍可读取。暂不新增“当前格答案”动作。
- **自主推理：**设置增加“自主推理”，旧设置默认关闭；开启后隐藏即时正误与数字余数/禁用，候选、智能草稿、自动清理依据可见填写。任何填写都按可见规则清理同行列宫候选，不以正确答案暗中区分；相关变化仍在同一撤销动作内。手动检查与解法保留为显式求助，错误与提示仍按既有成绩规则累计。

## 实现边界

本轮未更改题库映射、生成版本、积分规则、结果统一提交、账号或网络能力。备份、多局暂存、技巧专项练习等仍是后续范围。

本轮提供普通窗口适配，**没有新增原生铰链/折叠姿态桥接**。当前源码未实现向 Vue 页面提供折叠区域信息的桥接；不能用窗口宽度推断铰链位置、分隔或精确角度。后续取得原生能力后才能按真实区域安排书本/桌面姿态，避免完整棋盘和按钮跨遮挡区域。相关能力依据 [Android 折叠信息指南](https://developer.android.com/develop/adaptive-apps/guides/foldables/make-your-app-fold-aware)。

窗口变化与屏幕切换是不同的验证层次；厂商外屏是否开放普通 App、折叠是否触发 Activity/WebView 重建、系统如何恢复页面栈，需要实际安装包与真机确认。上下小折叠外屏按其运行能力验收，不能承诺系统未开放的使用方式。[Android 折叠屏指南](https://developer.android.com/develop/adaptive-apps/guides/foldables/learn-about-foldables)。

使用 uni-app 的窗口监听/解绑、页面 resize 和窗口信息读取；输入法导致的窗口缩小走同一布局路径，不把它误判为铰链姿态。[uni-app 窗口事件](https://en.uniapp.dcloud.io/api/ui/window.html)。
