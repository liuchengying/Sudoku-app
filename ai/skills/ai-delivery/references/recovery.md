# 恢复、调整和版本更新

在 next / inspect 报告异常、用户中途补充需求或需要升级时读取。只核对并推进当前相关任务，不把其他项目或历史交付一起返工。

next [ID] 是只读待办入口：action 表示当前建议动作，tasks 包含未结束任务、真实检查与剩余次数，counts 区分可推进、待验收、待恢复、受阻与已结束。多个候选不自动选择，AI 结合当前用户需求定位；仅在目标本身确实不清楚时询问。选择任务不等于获得新操作权限。它不会自动执行 action，也不会代填用户决定。

定位后先读 context ID，完整需求与条件保留，长计划明确摘录并有原文件路径。只有复杂异常再读取完整任务、历史和日志。begin/finish 是合并操作，不是合并质量门槛：begin 失败时按 received/planned 接续，不重新覆盖；finish 在 reviewed 后失败时依据失效原因恢复，再 deliver 或使用相同复核输入 finish。checkPolicy 漏项、未跟踪范围、空证明或原始结果不一致都需先修正实际原因。

## 恢复选择

| 实际情况 | AI 的处理 |
| --- | --- |
| received / planned | 完成相应计划后继续；不重复创建 |
| executing，最近一次失败 | 保留日志，说明修复，rework 后按原检查重新验证 |
| verified / reviewed / awaiting_owner 材料失效 | inspect 定位输入、检查、复核或交付变化；有可信快照可恢复原文件，否则 rework 后重新检查复核；不能催用户验收失效版本 |
| verifying，锁进程仍在 | 等待当前检查，拒绝并发写入 |
| verifying，进程已退出 | 记录中断原因，rework 后重新验证；工具归档陈旧锁 |
| 锁 JSON 损坏或 PID 不可判定 | 保留记录、核实持有进程，不猜测进程死亡、不强制解锁 |
| 任务 JSON 或计划缺失 | status 显示异常，inspect 定位；核对可信快照，不能伪造检查通过 |
| accepted / cancelled 后有新需求 | 建立新任务，保留历史记录；当前工作区失效不撤销历史验收 |
| 修复/检查上限用尽 | 呈现实际原因与现有结果；只有明确的新范围或任务才拆分，不通过重复建同名任务循环试错 |

next、inspect 和 doctor 只读。inspect 给材料、变化和尝试计数，doctor 核对配置及锁状态；都不会自动修复文件或启动工程。PID 存活检查只说明该 PID 存在，不能识别所有 PID 复用情形；工具不会自动终止进程。

用户明确取消可在任意未结束阶段用 decision cancel 记录。保存实际消息引用，保留已有检查、交付与取消前阶段；没有检查版本时 fingerprint 为 null。写锁存在时等待当前执行结束再记录；不能强制解锁或杀进程来取消。accepted/cancelled 不再接受决定。用户没有取消时，不能将坏记录、上限用尽或旧交付自动标为 cancelled。

## 用户补充需求

范围不变的小实现选择直接推进。有验收条件、请求、检查或必要范围变化时，由 AI 把完整新定义写入 docs，并说明为何属于用户已授权需求：

```text
ai-delivery --project <项目> amend <ID> --spec docs/intake/<ID>-amend.json --reason "用户补充内容或必要范围调整的实际原因"
```

工具先验证新定义，不能删掉已有检查，也不能修改已结束任务。旧 task、brief、plan 及已有 review/delivery 归档到任务 revisions；运行计数不清零，执行开始后的调整计入修复轮数。新任务回到 received，AI 完成新 plan、plan/start/verify/review/deliver，用户无需填写表单。

归档绑定哈希并参与交付门槛。不能改归档来美化历史，也不能把用户没有说过的确认写入 owner-input。用户确实改变目标且旧检查不适用时，保留旧任务，明确建立新范围，说明检查选择；不要用这种方式绕过已知失败。

## 更新公共工具

先在源码包完成行为回归和独立分发验证，再运行目标版本的 scripts/install.mjs install。安装器验证旧清单的拥有文件，新增目标有非拥有文件时停止，保留改动；清单内旧版已弃用文件只在哈希匹配时移除。

后来新增全局 AGENTS.override.md 时，重新 install 会将工具的精确路由段迁到有效文件，并保留两个文件的用户规则、附加内容和权限。目标已有别的路由标记时拒绝覆盖。

完成后核对安装 doctor、版本、文件哈希和目标项目 doctor；不要将安装成功当作模型行为全部通过。降级时用当前安装器卸载未改动的拥有文件，再从已保存的旧分发包安装；不要拿旧安装器直接覆盖新版。
