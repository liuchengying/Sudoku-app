# ai-delivery · 0.5.1

可移植的 AI 需求交付工具：**公共 Skill + CLI 引擎 + 项目适配器 + 项目内记录**。用户描述需求和最终验收，AI 管理中间文件和命令。源码不依赖数独、Vue 或固定目录。需要 Node 20 以上；项目检查工具由该项目提供，无新增 npm 依赖。

## 用户怎么用

安装后，在其他项目的新会话说：

> 使用 $ai-delivery 接入这个项目。按项目现有规则和脚本检查，以后我的开发需求都走这套交付流程。

AI 阅读项目并建立适配。之后直接描述需求，例如“首次进入页面时增加引导”；重要阶段会显示工具版本、任务、真实状态和检查结果，最终给交付包。只有你明确说“验收通过”才记录 accepted。无需操作任务命令。

也可明确说“使用 $ai-delivery 完成：……”。普通咨询不建立任务。新的技能和全局规则需在新会话加载；结构验证和文件安装不能证明模型在所有场景都正确触发，先在真实需求里观察回执。

当前版本以交付质量为先，提供完整的会话内交付路径。你可以直接说“完成这个需求……”“继续上次的需求”“退回修改……”“取消这个需求”或“验收通过”。AI 负责定位任务、核对上下文、实施与检查；重要阶段给实际状态和结果，最终给可审阅的交付包。接入新项目时仍需核实该项目的规则、检查工具及关键输入。

## 安装一次，在多个项目用

在本包目录运行（AI 可代办）：

```bash
node scripts/install.mjs install --dry-run
node scripts/install.mjs install
node scripts/install.mjs doctor
ai-delivery --version
```

安装 Skill 到 `~/.agents/skills/ai-delivery`，命令到 `~/.local/bin/ai-delivery`，向 `~/.codex/AGENTS.md`（若 override 已存在则使用 override）追加带标记的路由。现有规则保留；同名其他工具、符号链接或修改过的安装文件会拒绝覆盖。路径不在 PATH 时使用 `node ~/.agents/skills/ai-delivery/scripts/ai-delivery.mjs`。

安装副本自包含，源项目移动也能使用。安装清单保存每个文件的哈希；重复安装相同包不改文件。升级先检查旧安装未被修改，再从新包执行安装；允许新增资源，但保护目标路径已有的非拥有文件。后来出现全局 override 时，重装迁移工具路由并保留用户规则；不会自动下载或升级。详细恢复和降级见 [恢复与调整](references/recovery.md)。

### 在 ZCode 中使用同一技能

ZCode 官方用户级技能位置是 `~/.zcode/skills/ai-delivery`，支持软链接与复制导入。已有上面的公共安装时，可将这个位置链接到 `~/.agents/skills/ai-delivery`，使两端使用同一套脚本与资料；先核对同名目标，不覆盖其他技能。也可以在 ZCode 的技能设置页选择全局软链导入。[ZCode 官方说明](https://zcode.z.ai/cn/docs/skill)

0.5.1 修复目录或单文件软链接执行时入口未运行、空输出却返回成功的问题。CLI 与安装器按真实入口文件判断直接执行；项目配置和证据的路径保护保持原有规则。

安装后在 ZCode「设置 → 技能」点击刷新并确认启用，在新对话输入 `$ai-delivery 接入当前项目`，已接入项目可直接加上需求。ZCode 通过技能元数据选择技能；Codex 的全局 AGENTS 路由不等于 ZCode 的路由，是否自动调用应在 ZCode 真实会话中观察。

软链接依赖来源目录持续存在。公共安装更新后，ZCode 读取到相同版本；卸载或移动来源会使链接失效。跨机器或远程环境需重新安装或导入，不能只带走一个指向本机路径的链接。

卸载（仅处理工具拥有且未变化的安装文件和精确路由段）：

```bash
node ~/.agents/skills/ai-delivery/scripts/install.mjs uninstall --dry-run
node ~/.agents/skills/ai-delivery/scripts/install.mjs uninstall
```

卸载保留各项目任务与用户其他规则。若安装文件被你改过，先比较清单和改动，不能靠强删绕过保护。安装目录可用 `--home` 指向隔离目录测试。

## 三层职责

| 层 | 内容 | 复用方式 |
| --- | --- | --- |
| 公共工具与技能 | 状态机、证据校验、命令、AI 工作约定 | 用户安装一份，各项目调用 |
| 项目适配 | 跟踪范围、规则文件、脚本检查命令 | 每项目核实一次；与源码一起维护 |
| 需求记录 | 原始需求、计划、日志、复核、交付、用户决定 | 留在各项目 docs，互不混用 |

接入细节与 JSON 格式见 [项目适配说明](references/project-adapter.md)。默认新配置 `docs/ai-delivery/project.json`；兼容已有 `.ai-agent/project.json` 与 schema 1 任务，历史任务不迁写。现有项目 npm 别名可以指向本包或全局命令。

## 工具怎么起作用

```text
需求收件 → 计划 → 实施 → 项目脚本检查 → 逐项复核 → 交付 → 用户决定
                        ↓ 失败/输入变化
                        记录返工并重新检查（次数有限）
```

CLI 用任务文件保存状态，不允许跳过检查、复核和用户确认。源文件、适配配置、需求、计划、引擎及证据绑定指纹；状态和回执同时核对复核与交付材料，失效时显示原因并先恢复。inspect 提供材料、变化、尝试和锁状态。中途补充需求通过 amend 归档旧定义、保留运行次数并重新计划。重要状态自动刷新 `docs/workflow/STATUS.md`，CLI 回执供 AI 在进度消息里呈现。

AI 可用 begin 将包含具体 plan 的收件推进到执行，再 verify，最后用 finish 逐项复核并交付。三个操作覆盖原来六个阶段操作，保留阶段事件与全部门槛；缺计划、未通过检查、未解决问题或证据变化都不能交付。新会话通过 context 读取完整需求与验收条件、有限计划摘录及证据路径，不搬入全部历史基线和日志。长计划明确标记摘录，需要时读取原文件；完整约束不会静默截断。

项目可配置 checkPolicy，将基础检查及按修改范围触发的必要项固化，省略 checks 时自动选择；显式选择不能低于门槛。AI 仍判断规则外的风险并追加相应检查。源码范围不在 watch 或被排除时，先完善接入；任务记录和生成状态按既有资料目录处理。证明数组不能为空，检查摘要必须与本轮原始结果、必要日志及声明报告一致。状态查询只在单次操作内共享快照，后续操作与验证结束重新读取，不使用持久缓存掩盖变化。

AI 在新会话先用 `ai-delivery --project <项目> next` 查看待办。唯一进行中需求优先，多项候选由 AI 结合当前请求定位后使用 `next ID`；不擅自挑最新任务。待验收、待恢复、受阻与已结束数量来自当前材料检查，已结束历史不进入待办。next 不改文件、不运行检查；状态页和单项回执使用同样的动作判断。失败、中断、写锁和尝试上限会影响下一步，只有材料有效的交付才提示用户验收。

用户明确取消需求时，AI 可以在收件、计划或实施阶段记录 cancel，保留已有日志与取消前阶段。运行中的写锁仍需等待；取消不终止其他进程、不回滚源码。accept 与 return 仍在待验收阶段使用，不能以取消入口跳过验收门槛。

这是当前 AI 会话的工作工具；执行模型仍由 Codex 提供。没有后台队列、会话结束后持续执行器、独立多代理审核、身份认证、自动发布或云端服务。规则只能引导模型，门槛对通过 CLI 的流转生效，不能阻止任意直接改文件。注册检查不是安全沙箱，配置的脚本必须可信，权限沿用项目与用户约定。

工具减少机械操作和重复文件读取，模型 Token 与实际费用尚无测量数据。检查政策和 watch 由 AI 根据项目维护，工具不会自动推导所有隐式依赖，也不能仅凭退出码判断业务覆盖是否充分。脚本证据与真实使用反馈共同用于迭代质量。

## 验证与分发

```bash
npm test
mkdir -p dist
npm pack --pack-destination dist
```

测试包含通用状态约束、真实 Node/Python 检查、跨目录 CLI、安装幂等、冲突保护和卸载回滚。执行项目检查时移除上一级 Node 测试运行器的内部 NODE_TEST_CONTEXT，防止嵌套 node --test 跳过测试后错误返回成功；其他项目环境保留。只执行脚本，不启动应用。打包 tarball 可带到别的电脑解包安装；Node 和项目检查依赖在目标电脑准备。

当前包仅本地使用，尚未发布 npm、GitHub 或插件商店。未来可把这个自包含目录独立成工具仓库，保留项目适配方式；公共发布需由用户决定。Codex 技能发现和 AGENTS 入口参考 [官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills) 和 [官方 AGENTS 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。
