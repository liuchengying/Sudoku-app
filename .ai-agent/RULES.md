# 共同规则

本文件是 AGENTS.md 管理区块的维护源，由 `ai/scripts/install-entrypoints.cjs` 生成各客户端入口；修改后重新运行安装命令同步。用户约定和当前会话授权优先，本文件不扩大操作权限。

## 协作边界

1. 不操作 Git，尤其是 commit、push、分支与历史改写，除非用户明确要求；push、发布与 master 改写任何授权档位都不解除。
2. 不操控用户的电脑、浏览器或其他应用，除非用户明确要求。
3. 不启动本地工程（dev、watch、build、模拟器），除非用户明确要求。
4. 修改后的验证只运行注册脚本；未经明确授权，不通过启动应用或浏览器进行验证。
5. 新增文档、验证脚本、任务资料、运行日志及报告统一放在项目根目录 `docs/`，按用途和任务命名分类。
6. 普通咨询不创建任务，只读审查不修改业务代码。

## 授权档位（仅对当前任务有效）

- A 档（默认）：纯静态检查，只运行 `.ai-agent/project.json` 注册的脚本。
- B 档：允许为运行注册检查所必需的本地编译与测试环境操作；不启动 H5 预览或模拟器。
- C 档：在 B 档之上允许本任务的 Git 分支操作；push 等远端写操作仍由用户完成。

## 项目依据

- 修改前读取本文件、[当前工程概览](docs/PROJECT_OVERVIEW.md)、[架构说明](docs/ARCHITECTURE.md)、[项目交付规则](docs/workflow/RULES.md) 和需求涉及的实现；根目录 README 的早期描述与现有实现有差异时，以现有源码和当前工程概览为准。
- 数独 Core（`src/core/sudoku/`）保持纯 TypeScript；页面通过 Store 动作修改游戏，不能直接改格子绕开撤销、保存和回放。
- 结果统一提交和旧存档兼容约束、题库编号与生成版本约束按架构说明及相关源码执行。
- 不借流程接入、检查失败或用户验收扩大业务修改、Git、启动、发布权限。

## 交付约定

- 需求交付使用 `ai/skills/ai-delivery` 技能，状态写入统一走 `node ai/scripts/delivery.cjs` 薄入口；先 `next` 定位待办，再 `context` 接续，普通咨询不建任务。
- 检查由 `.ai-agent/project.json` 注册，风险与证据政策在 `.ai-agent/acceptance-policy.json`；失败不能删减检查或绕过门槛。
- 脚本通过、设备体验和用户验收分别如实说明；只有用户明确"验收通过 / 退回修改 / 取消"才记录 decision。
